## Контекст

Я працював Senior Software Engineer в ironSource і залишився на тій самій ролі в Unity після злиття компаній у 2022 році. Це платформа монетизації для розробників ігор. Нею користуються щодня, тому кожну зміну треба було випускати, не зупиняючи продуктову роботу.

**Стек:** TypeScript, Node.js, NestJS, gRPC, Protocol Buffers, Amazon SQS, React, Next.js, Terraform, CircleCI, GitHub Actions.

## Рішення

### 1. Спершу продуктивність

Я почав із того, що з’ясував, куди йде час запитів. Частину вдалося оптимізувати на місці, а важчу роботу винесли в асинхронну обробку, тож запити більше на неї не чекали.

### 2. Модернізувати бекенд поступово

Я запропонував перевести бекенд на NestJS заради єдиної модульної структури й очолив цей перехід. Він ішов малими кроками, кожен з яких можна було відкотити, і продуктова робота тим часом тривала.

**Ціна:** перехідний період, коли коду для підтримки більше, зате жодного ризикованого релізу «все й одразу».

### 3. Аналітичні дашборди

Я відповідав за аналітичну частину фронтенду продукту: дашборди, графіки й екрани з метриками, за якими розробники ігор стежать за своїми показниками. Будував їх на React і Next.js, дані отримував через TanStack Query, таблиці робив на TanStack Table.

### 4. Типізовані контракти між сервісами

Я запропонував і впровадив gRPC між сервісами. Типи клієнта й сервера ми генерували зі спільних визначень Protocol Buffers.

## Також в Unity та ironSource

- Інфраструктура AWS як код на Terraform; CI/CD у CircleCI та GitHub Actions.
- Власні skills і агенти для Claude Code, що автоматизують повторювану інженерну роботу.
- В ironSource: функції у фронтенді й бекенді self-service платформи для монетизації та зростання застосунків.
